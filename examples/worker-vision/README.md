# 视觉核心

视觉核心是 Modot 内置的任务核心预设。它用另一模型分担选图、图像识别和易混字符复核。

## 实测收益

在 Terminal-Bench 2.1 的 `gcode-to-text` 原题上，**DeepSeek Flash 单模型正式运行 0/5。接入视觉模型后，三次诊断交付通过了官方检查。** 双模型分工时，DeepSeek 从原始刀路重新渲染，GLM-5.3-Flash 按新投影精确转写，提交文件获得 **2/2（reward 1）**。另外两次由父核心直接调用 GLM 读图，也通过了文件存在和内容精确匹配两项检查。

视觉核心预设让父核心可以把整段视觉工作委派出去。在独立图片验收中，GLM 运行视觉核心并复核两个视图，DeepSeek 收回结构化成果，写出了逐字匹配的交付文件。[官方题试次与视觉核心验收](../../docs/benchmarks/modot-engineering-scorecard.md#视觉核心的实测收益)

## 启用和使用

1. 在 **设置 → 模型** 连接支持图片和工具调用的供应商与模型，也可使用自定义兼容端点。
2. 在 **任务核心预设 → 视觉核心模型** 选用该连接。视觉核心需要与父核心不同的模型，同一供应商的另一模型也可以。
3. 启用 **视觉核心**。配置从下一次运行开始可用于委派。

接到委派后，视觉核心从授权项目资料选择最多三张视图，包括完整投影和必要的局部。宿主按实际图像摘要去重，集中请求已配置的视觉模型，并在收到候选时立刻保存正文、不确定字符和图像依据。一次批量转写的模型请求及重连共用 90 秒时限。有疑点或首次失败时可换视图发起一次追加批次。父核心可先读取候选交付，项目写入仍需当前权限和版本。视觉批次沿用现有模型预算和授权检查。

父核心也可以在自己的 L0 会话内直接投影和读图。配置了视觉核心模型时，它仍可直接请求该模型做单图精确转写。启用预设后，父核心还可以把选图、复核和组织证据的整段工作委派出去。
