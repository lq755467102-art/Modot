# 探路者

把一个能影响下一步决定、又能独立查证的未知点交给探路者。例如执行者调整导出接口，探路者查旧 CLI 是否显式传入格式。用 `question` 说明要回答的问题，用 `scope` 写负责的调用方或文件，用 `tried` 附已知结论和出处。调查结果中的每条观察带来源和适用版本，执行者决定如何使用。

CLI 证据已足够支持父方保留旧调用方式。还有独立调查时，可以用 `submit_worker_result` 先交这条带版本的证据，待出现新发现再用新的 `submission_key` 补交。重试同一份成果时沿用原键。普通进度留在子会话，父方收到成果标识后自行决定是否读取。

在 Modot 的插件页选择本目录，预览后安装，在详情里启用“子 Agent 贡献”。下一轮从 `plugins` 工具组调用 `inspect_worker_plugins`，使用返回的 `worker` 标识。探路者可以单独安装运行。

[示例](example.json) 包含一对有效的 `input` 和 `output`。[声明](plugin.json) 定义了只读调查的方法和结构。父方传 `kind: "report"`、问题、范围、已试路线和明确选中的资源。子实例从自己的运行事实取得派生的资源 ID。示例中的 `example-v1` 在实际读码时应换成所读文件的 `revision`。需要运行探针但委派只有读权限时，可提交空 `findings`，在 `unknowns` 写出待核对事项。

开发自己的版本时，复制目录并改包名、贡献名、Schema 和方法，使结果能区分观察与推断。用有未提交改动的临时项目验证只读边界，修改源文件后确认执行者仍能看出成果适用的旧版本。完整的注册、失败、续接与回收过程见[开发与验证指南](../../docs/protocols.md)。
